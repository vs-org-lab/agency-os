# Sub-projeto 1B — Diagnóstico Aurion Core — Plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: usar `superpowers:subagent-driven-development` ou `superpowers:executing-plans` para executar este plano tarefa a tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** levar o Aurion Core para o OS: briefing em modo call, auditoria com prova, Índice Orbit, roadmap em três faixas, revisão cruzada, apresentação Figma no portal e a etapa 1 do pipeline com critérios.

**Arquitetura:** novo módulo `apps/web/src/modules/diagnosis` (domínio puro + serviços com dependências injetadas + `server.ts`) e novo módulo `apps/web/src/modules/documents` (o 1C alarga-o). Tabelas novas com RLS FORCE e privilégios por coluna; o portal lê só colunas partilháveis. As provas carregadas vão para um bucket privado do Supabase Storage atrás de uma porta `EvidenceStorage`. O Core nasce no consumidor Inngest de `commercial.call.booked`; os critérios da etapa 1 entram na matriz de transições como factos.

**Stack:** a do 1A, mais `@supabase/supabase-js` (já instalado) para o Storage. Sem dependências novas.

**Spec:** [docs/superpowers/specs/2026-10-08-core-design.md](../specs/2026-10-08-core-design.md)

## Foco de revisão

1. **Duas pessoas a escrever no briefing ao mesmo tempo (fundador em modo call e gestor no separador Core):** gravar um bloco nunca apaga a nota de outro bloco nem a de outra pergunta. Teste na Task 6 (`saving one note leaves the other notes untouched`).
2. **Ficheiro com extensão `.png` que não é imagem, ou com mais de 10 MB:** recusado antes de chegar ao Storage, com mensagem clara. Testes na Task 7 (`rejects a file whose content is not an allowed type`, `rejects files above 10 MB`).
3. **Link do Figma colado de outra origem ou mal formado (por exemplo `figma.com.evil.io`, `http://`, texto solto):** recusado; só `https://www.figma.com/...` ou `https://figma.com/...` são aceites. Teste na Task 9 (`accepts only https figma.com links`).
4. **Negócio do Core pausado (X.1) e reaberto:** volta ao código anterior sem reavaliar os critérios da etapa 1; recuar um código com motivo pelo fundador continua possível. Teste na Task 4 (`reopening a paused Core returns to its code without checking criteria`).
5. **Cliente com acesso ao portal antes de qualquer partilha, ou utilizador de outro cliente:** não vê briefing, achados, pontuações nem documentos em rascunho. Testes nas Tasks 1 (`portal user sees nothing before sharing`) e 14 (`portal home shows the empty state before sharing`).

**Interfaces:**
