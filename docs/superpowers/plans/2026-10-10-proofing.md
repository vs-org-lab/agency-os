# Sub-projeto 2D.1 — Proofing de ficheiros — Plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: usar `superpowers:subagent-driven-development` ou `superpowers:executing-plans` para executar este plano tarefa a tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** a equipa carrega imagens, PDFs e vídeos para aprovação; o cliente comenta em pontos ou momentos e decide; as rondas contam e avisam.

**Arquitetura:**

- Módulo novo `apps/web/src/modules/proofing`: domínio puro (tipo pelos primeiros bytes, âncoras, rondas), serviços (ficheiros, versões, comentários, aprovação de versões), Storage e automações.
- As aprovações de versão reutilizam a tabela `approvals` do 2A (`subject_type = 'file_version'`) e a decisão `decideApproval`, que passa a tratar os dois tipos.
- Visualizador partilhado em `components/proofing` para a sala e o portal; PDF desenhado com `pdfjs-dist`.

**Stack:** a do 2C mais `pdfjs-dist` (sem custo).

**Spec:** [docs/superpowers/specs/2026-10-10-proofing-design.md](../specs/2026-10-10-proofing-design.md)

## Restrições globais

- As dos planos anteriores: TDD; inglês no código e PT-PT na documentação; migrações com dry-run e nunca com o e2e do CI a usar a base de dados; sem custo; sem linhas de atribuição a IA.
- **Valores do spec:** tipos PNG, JPEG, WebP, PDF, MP4, WebM; 50 MB; links assinados de 15 minutos; limite de rondas 3 por defeito; aviso a 80%; tarefa "Orçamentar ronda extra".
- **Regras:** comentários internos nunca chegam ao cliente; só o decisor decide; pedir alterações exige comentário; versões só visíveis ao cliente depois do pedido de aprovação; acesso por projeto (`app.can_read_project`).

## Foco de revisão

1. **Ficheiro com extensão de imagem e conteúdo de outro tipo:** recusado e apagado. Teste na Task 2 e na Task 3 (`a spoofed file is rejected and removed`).
2. **Versão nova com pedido pendente na anterior:** o pedido anterior é retirado e o cliente decide só a versão atual. Teste na Task 4.
3. **Operacional e freelancer fora do projeto:** sem comentários internos e sem ficheiros, respetivamente. Teste na Task 1.
4. **Aviso de 80% repetido:** uma única vez por projeto e limiar. Teste na Task 5.
5. **Âncora fora dos limites (x > 100, página inexistente, segundo negativo):** recusada. Teste na Task 2 e na Task 4.

### Task 2: Domínio do proofing

**Ficheiros:** `modules/proofing/domain/{file-type,anchors,rounds}.ts` (+ testes).

**Interfaces:**

- `detectProofType(bytes: Uint8Array): { kind: ProofKind; mimeType: string } | null` pelos primeiros bytes: PNG, JPEG, WebP (`RIFF…WEBP`), PDF (`%PDF-`), MP4 (`ftyp` no byte 4), WebM (`1A 45 DF A3`).
- `parseAnchor(kind: ProofKind, input: unknown, pages: number | null): ProofAnchor | null | 'invalid'` com `ProofAnchor = { type: 'point'; x; y } | { type: 'page_point'; page; x; y } | { type: 'time'; seconds }`; `null` para comentário geral; x e y entre 0 e 100.
- `roundsStatus(used: number, limit: number): { used; limit; warning: boolean; extra: boolean }` — `warning` a partir de `ceil(0.8 * limit)`, `extra` quando `used > limit`.

**Passos:**

- [ ] Escrever os testes: `detects each accepted type`, `rejects a renamed file`, `anchors stay inside the file`, `warns at eighty percent and flags the extra round`.
- [ ] Correr e ver FALHA → implementar → PASSA → commit.

### Task 3: Ficheiros e versões

**Ficheiros:** `modules/proofing/{storage,supabase-storage,files,index,server,testing}.ts` (+ `files.db.test.ts`); auditoria.

**Interfaces:**

- `ProofStorage = { createUploadUrl(path): Promise<string>; read(path, bytes: number): Promise<Uint8Array | null>; signedUrl(path, ttlSeconds): Promise<string>; remove(path): Promise<void> }`.
- `createProofFile(claims, { projectId, phaseId?, title }, deps)` → `{ ok: true; fileId; versionId; uploadUrl }` (fundador e gestor atribuído; cria a versão 1 em `uploading`).
- `addProofVersion(claims, { fileId }, deps)` → `{ ok: true; versionId; uploadUrl }`.
- `confirmProofVersion(claims, { versionId, sizeBytes, pages? }, deps)`: lê os primeiros bytes, `detectProofType`; aceite → `ready` com tipo e MIME; recusado → `rejected` e ficheiro apagado (`rule: 'invalid_file'`); mais de 50 MB → recusado.
- `proofFileUrl(claims, versionId, deps)`: link de 15 minutos para quem lê a versão (equipa ou cliente pela vista).

**Passos:**

- [ ] Escrever os testes: `manager creates a proof and confirms an image`, `a spoofed file is rejected and removed`, `freelancers cannot upload`, `signed links only for readers`.
- [ ] Correr e ver FALHA → implementar → PASSA → commit.

### Task 4: Comentários e aprovação de versões

**Ficheiros:** `modules/proofing/{comments,approvals}.ts`, `modules/rooms/approvals.ts` (+ testes); eventos e auditoria.

**Interfaces:**

- `addProofComment(claims, { versionId, body, anchor?, internal?, parentId? }, deps)`: equipa da sala (interno permitido) ou cliente decisor/operacional (nunca interno); número sequencial por versão; evento `proofing.comment.added` `{ versionId, commentId, byClient, internal }`.
- `resolveProofComment(claims, { commentId, resolved }, deps)`: equipa.
- `requestVersionApproval(claims, { versionId }, deps)`: só a versão atual e `ready`; retira o pedido pendente de versões anteriores; evento `rooms.approval.requested`.
- `decideApproval` aceita `file_version`: aprovar ou pedir alterações (comentário obrigatório); pedido de alterações conta a ronda; acima do limite marca `extra_round`, cria a tarefa "Orçamentar ronda extra" (origem `manual`, ao gestor único do cliente, data +2 dias) e emite `proofing.round.extra`; ao cruzar 80% emite `proofing.rounds.warning` uma vez por projeto e limiar.
- `setRevisionLimit(claims, { projectId, limit }, deps)`: fundador e gestor atribuído, 1–20.

**Passos:**

- [ ] Escrever os testes: `client comments on a point and the team replies`, `clients never post internal comments`, `a new version withdraws the pending request`, `change request counts a round and the fourth is extra`, `the warning is emitted once`, `anchors outside the page are refused`.
- [ ] Correr e ver FALHA → implementar → PASSA → commit.

**Interfaces:**

- `loadProofs(claims, { clientId, projectId }, deps)` (equipa) e `getClientProofs(tx, clientId)` (portal) → `ProofFileView[]` com versões, aprovação atual e comentários.
- `loadProofVersion(claims, versionId, deps)` e `getClientProofVersion(tx, versionId)` → versão com comentários (o cliente sem internos) e `rounds: RoundsStatus`.
